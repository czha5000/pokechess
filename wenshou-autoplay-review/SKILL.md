# 自动打一局 + 复盘 + 调平衡

目标:用无头模拟器自动打**完整一局(三章)**,复盘这局的得失,基于这局(并用小批量确认)对游戏平衡做**一次有依据的微调**。
数值从真实 `js/data/*` 读取,改动只动 `js/data/config.js`。

## 前置
- 工作目录:项目根 `纹兽战记/`。平衡台在 `balance/`。
- 关键旋钮在 `js/data/config.js`:`ENEMY_POWER`(普通敌人血/攻倍率)、`BOSS_HP`(Boss血倍率)、`CH_SCALE`(各章缩放)、`THRESH`(经验曲线)、`STAGE_LV`(进化等级)。
- ⚠️ 一局是**轶事**(高方差),不能只凭一局拍板;本流程要求改动后用**批量(≥50局)确认**,避免过拟合到这一局的运气。

## 流程(每次按序执行)

**1) 自动打一局(带逐步过程)**
```bash
cd balance
TRACE=1 node sim.js 1
```
输出 = 这一局的逐回合决策(部署/移动/用招/目标/胜负)+ 该局的汇总(通关到第几章、阵亡几只、各 Boss 回合、进化阶段、克制占比)。

**2) 复盘得失(按模板写)**
- **结果**:通关 / 第几章哪种节点失败。
- **关键时刻**:在哪一场被打崩 / 哪个敌人最难处理 / 谁阵亡、为什么。
- **成长**:一章末是否二段进化、三章是否三段;哪些单位没成长起来。
- **克制利用**:super(×2) 占比高不高,是否被"全普攻"之类阵容钻空子(如幽灵免疫)。
- **节奏**:平均回合/场、Boss 回合是否在 4–6。
- 用 2–4 句话点出**这局最突出的 1 个平衡问题**。

**3) 据此提出并落地一次微调**(对照下表,只改 1–2 个旋钮,小步)

| 这局信号 | 调什么(`js/data/config.js`) | 方向/幅度 |
|---|---|---|
| 轻松通关、没什么险情 | `ENEMY_POWER` / `BOSS_HP` | ↑ 约 +0.1~0.2 |
| 早早团灭 / 频繁阵亡 | `ENEMY_POWER` / `BOSS_HP` | ↓ 约 -0.1~0.2 |
| 某一章明显过难/过易 | `CH_SCALE[该章]` | ±0.1~0.2 |
| Boss 几回合就被秒 | `BOSS_HP` | ↑ |
| Boss 拖过 8+ 回合 | `BOSS_HP` | ↓ |
| 进化太晚/太早 | `STAGE_LV` 或 `THRESH` | 调阈值 |
| 被单一套路(如幽灵免疫)碾压 | 数据层:给部分野怪掺非普通招(`js/data/creatures.js` 的 `skills`) | 加 1 个元素招 |

落地 = 用编辑器改 `config.js` 对应字段(蓝色输入值)。**每次只动最小幅度**。

**4) 批量确认(防过拟合)**
```bash
node sim.js 60
```
对照目标区间:**通关率 65–80%、各章无单章阵亡尖峰 >15%、Boss 4–6 回合、克制 super ≥15%**。
- 若落进区间 → 保留改动。
- 若过头 → 回调一半,再跑一次。

**5) 记录**
在 `CHANGELOG.md` 顶部追加一条:改了哪个旋钮(旧→新)/ 触发它的那局复盘要点 / 批量确认的前后数字。

## 重要约定
- **AI 水平**:sim 用的是 v2 启发式(威胁加权/躲反击/暴露走位/残血撤退,见 `balance/SKILL.md`)。它不是真人也不是 LLM 现场决策;平衡按"会玩的基准玩家"校准。
- **公式 vs 数值**:本流程只改**数值**(config/creatures),sim 自动同步。若改了**战斗公式**(`js/core/combat.js` 的命中/暴击/伤害/经验),必须同步改 `balance/sim.js`,否则复盘失真。
- **收服未纳入 sim**:平衡台目前不模拟收服,复盘里"该不该收强敌"需人工判断。

## 一句话
跑 `TRACE=1 node sim.js 1` 看一局 → 写复盘 → 据最突出问题改 `config.js` 一个旋钮 → `node sim.js 60` 确认落进 65–80% → 写 CHANGELOG。
