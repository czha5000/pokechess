# 纹兽战记 · 平衡台 (balance bench)

自动"试玩"= 用 `balance/sim.js` 跑大量模拟局(不点真实 UI),复刻战斗结算 + 速度交错行动 + 启发式 AI。
**数值不漂移**:模拟器通过 `balance/loadData.js` 直接读取游戏真实数据文件 `js/data/*.js`(属性表/招数/怪物/遗物/配置),改游戏数值后无需改模拟器。

## 怎么跑

```bash
cd balance
node sim.js [局数]            # 默认 100 局,用 js/data 当前数值
# 旋钮(环境变量,用于试探"改成这样会怎样",不改源文件):
EH=2.0 node sim.js 100        # 普通敌人 血/攻 倍率
BH=2.6 node sim.js 100        # Boss 血量倍率
EC=1   node sim.js 100        # 普通战额外敌人数
DEPTOT=4 node sim.js 100      # 我方出战总数
RELICS=power_band,exp_necklace node sim.js   # 给玩家装备遗物(测 build/Meta)
STARTLV=2 node sim.js         # 起始等级(测 Meta 加成)
```

旋钮只影响这次试探。确定要改后,再去 `js/data/config.js`(`ENEMY_POWER`/`BOSS_HP`/`CH_SCALE`/`THRESH`/`STAGE_LV`)或对应数据文件落地。

## 指标与目标区间(评测 AI = 中等水平)

| 指标 | 目标带 | 解读 |
|---|---|---|
| 通关率(基线:无遗物/Lv1) | **65–80%** | AI 78% ≈ 真人熟练 45–60%。>85 太易,<55 太难 |
| 各章通过率 | 平滑递减,**无单章阵亡尖峰 >15%** | 某章骤降=该章难度尖峰 |
| Boss 平均回合 | **4–6** | <3 被秒;>8 拖沓 |
| 平均回合/场 | **3.5–5** | 太低=互秒,太高=磨 |
| 一章末二段进化 | **≥60%** | 验证 Lv4 节奏 |
| 三章末三段进化 | **≥50%** | 验证 Lv7 节奏 |
| 克制 super 占比 | **≥15%(理想)** | 当前~11% 偏低,克制爽点不够 |
| Meta 满级+遗物 通关率 | **不应长期 100%** | 当前会到 100% → Meta 增益偏强,需关注 |

## 超出区间 → 调什么(对照表)

- 通关率过高 → `ENEMY_POWER`↑ / `BOSS_HP`↑ / `EC+1` / `DEPTOT−1`
- 通关率过低 → 上述反向
- 某章阵亡尖峰 → 调该章 `CH_SCALE[ch]` 或该章 Boss 数值(`CH_BOSS`)
- Boss 回合过短 → `BOSS_HP`↑(优先,而非提攻击,避免秒人)
- 克制 super 占比低 → `SKILLS.basic.mult`↓ / 元素招 `mult`↑ / 给敌人更多样的属性
- Meta 状态碾压 → 降低 `meta.js` 的起始等级幅度/起始遗物强度,或抬高基线难度

## 维护(避免漂移)

- **数值类**(怪物/招数/遗物/章节缩放/经验曲线):只改 `js/data/*`,模拟器自动跟随。
- **战斗公式类**(命中/暴击/伤害/经验/进化逻辑):同时改 `js/core/combat.js` **和** `balance/sim.js`(公式在 sim 里是手写复刻的,二者需保持一致)。每次改完跑 `node sim.js` 对比基线确认未跑偏。

## 步骤记录(供"在真实游戏里看一两局")

```bash
TRACE=1 node sim.js 1      # 打印第1局的逐步决策:部署→每单位 移动/用招/目标→敌方→胜负
```

### AI 决策策略(这就是"步骤"的算法;任何执行器都按它复演)
1. **部署**:必带伊布(主角);其余按 (等级×10 + 攻 + 血/5) 排序取前 3 自选;再随机补到 5。
2. **伊布开战变身**:选「对全场敌人 typeMult 之和最高」的形态(火/水/雷)。
3. **行动序**:所有存活单位按速度降序(同速我方优先),逐个行动(敌我交错)。
4. **我方每单位**:枚举(已学的每招 × 每个敌人),找可达且射程内的最近落点;期望伤害 = 基础伤害 × 命中率 ×(二段?2:1);评分 = 期望 +(可击杀?+20)+(克制?+6) −(免疫?−100);取最高执行;无可打则向最近敌人移动。
5. **敌方**:按 typeMult×mult 选最优招/目标(再按低血),移动进射程后攻击;我方在射程内会反击。
6. **成长**:命中即得经验(×1.4,击杀+5);Lv4/Lv7 触发进化。

## ⚠️ 关于"无头录动作 → 真实UI回放"的风险

直接把本模拟器录下的动作丢给"另一个技能在真实游戏里回放",**会失同步、基本不可行**,原因:

- **两套引擎、两条随机流**:命中/暴击/收服/刷怪/地图生成/敌方AI 都各自 `Math.random`。第一个随机事件后,双方棋盘状态就分叉——录的"移到(5,3)打3号敌人"在真实局里目标可能不存在 → 动作越界/失效/报错。
- **录的是"相对状态的动作"**,依赖目标在特定位置/血量,不是绝对指令。
- **地图、随机补员、敌人布点也都不同**。
- **公式漂移**:sim 是手写复刻,任一处与 `combat.js` 不一致就偏离。
- **没有共享种子**:要严格复现,需给"游戏"和"模拟器"注入**同一个 seeded 伪随机**且调用次序完全一致——极脆,任何地方多调一次 random 就整条错位。
- **UI 驱动**:模拟点击受动画 / 弹窗 / `busy` 守卫 / 时序影响,易卡死。

### 推荐做法(替代方案)
- **方案A(推荐,看一两局用):** 把**同一套上面的决策策略**做成游戏内 `js/autoplay.js`,直接调用游戏真实函数(`selectUnit`/`doMove`/`execAttack`/`doCapture`/`advanceInit`)带延迟自动开打。你看到的是**真实引擎**在跑、有动画、游戏日志即步骤记录——**零漂移**,因为用的就是游戏本体。两个技能共享同一份策略文档(本节)。
- **方案B(要严格复现时):** 把模拟器与游戏统一到**单一引擎 + seeded PRNG**,用「种子」复现整局(录种子,不录动作)。工作量大但严谨。
- **结论:** "看一两局演变" → 做**游戏内 autoplay(方案A)**;平衡台保持无头(快)。**不要**用"录动作→真UI回放"。

## 进阶(可选 agent)

若要"无人值守自动调参":写一个外层脚本/agent,用本 skill 的旋钮做网格搜索,循环跑 `sim.js` 直到通关率落入 65–80% 且各项达标,输出最优 `config.js` 数值。本 skill 提供单次评估能力,agent 负责迭代收敛。
